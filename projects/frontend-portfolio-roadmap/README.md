# Frontend Engineer Portfolio — Two Flagship Projects

Blueprint based on the supplied 8-week roadmap. Build **your-ui** first, then reuse it in **syncboard**.

- [your-ui](./your-ui/README.md): React/TypeScript accessible component library and playground.
- [syncboard](./syncboard/README.md): collaborative Kanban board with a React client and Fastify/WebSocket server starter.

## Roadmap
Weeks 1–3: design tokens, accessible components, component tests and documentation.
Weeks 4–5: board CRUD, WebSocket updates and presence.
Week 6: IndexedDB outbox, offline/reconnect replay and conflict handling.
Weeks 7–8: virtualization, Playwright E2E, Lighthouse budgets and deployment.

Evidence such as screenshots, audit results, coverage, performance numbers and demo GIFs must be generated from real runs. Do not claim unmeasured metrics.

## Evidence and quality gates

- [Evidence guide](./EVIDENCE.md): how to generate and interpret screenshots, test reports, accessibility results and performance metrics.
- [Playwright test suite](./evidence/tests/): UI behavior tests and automated axe-core scans for both projects.
- [Lighthouse CI configuration](./evidence/lighthouserc.json): repeatable performance, accessibility and best-practices audits.
- [GitHub Actions workflow](../../.github/workflows/portfolio-evidence.yml): builds both frontends and the server, runs browser checks, and uploads reports as workflow artifacts.

When a workflow run completes, open the repository's **Actions** tab and download the `portfolio-test-evidence` and `portfolio-lighthouse-reports` artifacts. Screenshots, traces, HTML/JSON test reports and Lighthouse reports are generated by the workflow. They are not checked in as if they were verified before a run.

**Current evidence status:** the tooling and workflow are committed; no passing test, accessibility score, or performance number is claimed until the workflow actually runs and produces results. Axe automation is a partial accessibility check, not a full WCAG certification.
