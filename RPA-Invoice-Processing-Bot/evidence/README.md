# Evidence checklist — capture real outputs

Capture these from your own Automation Anywhere A360 Community workspace. Use synthetic invoice/supplier data and mask any personal or customer information.

## A360 execution proof
- [ ] A360 bot canvas showing folder discovery and file loop
- [ ] CSV and Excel read actions with column mapping
- [ ] PDF extraction/OCR action and extracted field values
- [ ] Supplier master lookup, active/inactive decision and GST comparison
- [ ] Within-batch and database-backed cross-run duplicate check
- [ ] Validation branches and exception/error handlers
- [ ] Approved, Review, Rejected and Exceptions folders after a run
- [ ] A360 run details with run ID, start/end time and final status
- [ ] Database query results showing accepted invoices and no duplicate row after rerun
- [ ] CSV processing report
- [ ] Excel processing report
- [ ] PDF processing report
- [ ] Actual received email and report attachments (only if SMTP is configured)

## Python reference proof (label separately from A360)
- [ ] `pytest` output from the repository's CI or local run
- [ ] Example CSV/XLSX/PDF reports generated by the Python reference
- [ ] SQLite query showing approved invoices and processing events
- [ ] Duplicate-across-runs test result
- [ ] Supplier-mismatch and corrupt-PDF exception test results

## Integrity rules
- Do not present seeded/demo data as live supplier records.
- Do not present Python output as A360 execution evidence.
- Do not claim OCR, SMTP delivery or database connectivity until the actual configured integration has been run successfully.
- Never commit credentials, real invoices, supplier personal data or unredacted screenshots.
